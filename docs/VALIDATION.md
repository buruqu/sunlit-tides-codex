## 1.2.1 60 帧与可见摆动

- 用户反馈 20fps 和不足半像素夜景摆幅不够明显，本版改为纯 RAF 60Hz 目标调度，并把 WebGL 绘制与动画时钟移到独立 Worker。初版主线程实现虽在独立测试达到 60fps，当前 Codex 界面长任务下只有约 40–50fps，因此没有止步于提高帧率上限。转移的画布直接提交合成器，不通过界面线程逐帧回传图片；不支持 Worker 时使用同一 GPU 后端回退。
- Worker 专项 12/12 通过：实际 DedicatedWorker 的 WebGL 调用插桩确认，在界面主线程连续执行 250ms 阻塞八次期间，2.441 秒完成 147 次真实清屏、1029 次绘制，约 60.216fps，最大帧间隔 16.9ms。异步取帧确认动画时间与像素继续变化；零时刻原图差异为零，六个固定区变化为零。切换清理、异步请求取消、暂停恢复及无 Worker 回退通过。
- 两段最终预览直接录制实际 Worker 画布，不逐帧回传给主线程、不加速。7.2 秒录制期间绘制约 60fps；果园 960×960 的 VP8 实际编码 58.47fps，夜景 960×640 为 60.01fps。三个时间点解码均为有效、自然变化的画面。较早 1280×1280 VP9 录制因实时编码负载掉到 54.71fps，最终预览降低编码负载；这不是背景绘制的降帧。
- 普通鼠标移动不暂停，输入、滚动和拖拽暂停保留。60 / 120 / 144Hz 调度、时间误差、掉帧与暂停恢复六项确定性检查通过。共享 GPU 后端的动态专项 30/30 通过，逐帧布局和计算样式读取为零。帧率是本次环境测量，不承诺所有设备负载下恒定 60。
- 果园在 t0、t0.9 的 Worker 与主线程后端逐 RGBA 通道差异均为零，包含 26,485 个源透明轮廓像素；运动相位的线性过滤边缘也一致。独立只读审查确认消息顺序、首次显示、时钟、资源释放和失败回退，无剩余可行动问题。
- 禁用光影与眨眼后，夜景真实运动影响 6316 个源像素（0.586%），六片各有 410–1983 像素变化，真实自由端采样位移约 2.37–4.88px。果园六片自由端诊断位移 5.48–7.60px，各有 3283–44022 像素变化，正常尺寸对照另作人工验收。
- 新增较长粉发与袖口的自由区域，边缘补色只在动作孔内最多 9px，从所有动作蒙版之外取相邻原像素；纹理重建仍保证夜景 t0 与原图 RGB 差异为零。固定区、四眼分组、相册切换清理与所有静态回退通过。
