# Shared DIY editor

`diy-editor.js` is a plain JavaScript IIFE. Concatenate it before either host adapter, then call:

```js
const editor = mountSunlitDiy({ window, document, platform: 'codex', adapter, cssText });
// A button inside the existing palette calls editor.open().
// Its “DIY” action may call editor.startEditing() directly.
```

`cssText` is optional. The core has the same complete fallback CSS as `diy-editor.css`, scoped inside an open ShadowRoot. It creates no permanent launcher. Its host is `[data-sunlit-diy-editor]`; host observers should ignore this subtree. Public methods are `open()`, `startEditing()`, `refresh()`, `dispose()`, `getState()`. `window.__SUNLIT_DIY__` references the active instance. Mounting a replacement disposes the previous instance.

The adapter provides `getMode()`, `getBuiltins(mode)` and `apply(layers, typography, mode)`. Descriptor rectangles use viewport pixels; editable rectangles use viewport percentages. `apply` receives complete override layers, including disabled builtins, plus the unconfirmed preview when present. Unmodified builtins are absent, so the original appearance and animation remain owned by the host. Reset and disposal send `[]` and `null`. A region never rotates. Stable builtin ids are `background`, `sidebar`, `portrait-left`, `portrait-right`, `emote-left`, `emote-right`, `effect-default`, `sidebar-region`, `chat-region`, `composer-region`.

Descriptors may specify `fit: 'contain' | 'cover'`; the core preserves it. The optional synchronous pure function `adapter.constrainLayer(layer)` receives a complete independent layer copy and returns a constrained copy. For region layers, the core accepts only finite `x/y/width/height` from this result. Readout, numeric editing, pointer gestures, layout boxes and adapter application use the same effective geometry, including after project load and viewport changes. The adapter must not mutate DOM, call `apply` or call back into the core from this function. Default layers remain absent from overrides; viewport recomputation never saves a project. `getState().layers` and saved snapshots retain raw user-authored values, while visible geometry and `apply` reflect current constraints.

Layer fields: `id`, `name`, `kind`, `builtin`, `source`, `enabled`, `locked`, `x`, `y`, `width`, `height`, `rotation`, `flipX`, `opacity`, `z`, `fit`, `blur`, `effect`. `effect` includes `preset` (`leaf`, `bubble`, `custom`), `count`, `size`, `speed`, `direction`, `sway`. Optional `assetId` identifies an imported asset; optional `sourceRef: true` identifies a trusted builtin resource resolved from the current adapter descriptor. `apply` always resolves these references to the actual source. Builtin ids, kinds and `builtin: true` are strictly bound: custom layers cannot use reserved ids, and a region id cannot masquerade as an image/effect. Builtin opacity and enabled state are inherited exactly from descriptors. Names are rendered with `textContent`.

Optional `lockAspect` defaults to true for portrait/emote/image and false otherwise; regions cannot enable it. `aspectRatio` is pixel width divided by pixel height, never the ratio of percentage fields. Missing fields in legacy projects are inferred from the current displayed rectangle without changing its initial appearance. Newly imported assets use decoded pixel dimensions. Width, height and the corner resize handle share the same aspect calculation; turning the lock on captures the current ratio. If an extreme ratio has no solution within both axes’ 0.1–200% range, the effective lock turns off, legal geometry is retained, the checkbox follows that state and the panel explains the fallback. `contain` continues to preserve the actual image ratio. An explicit user edit commits that fallback; viewport-only fallback changes the effective view without rewriting the saved project. Effective locked-layer dimensions otherwise retain their pixel ratio when viewport dimensions change. The positioning actions “水平居中 / 垂直居中 / 移回画布” operate on both pending previews and confirmed layers and participate in undo history.

Every interaction commits geometry through the same schema bounds, including keyboard, numeric input, pointer gestures and positioning actions. “移回画布” clamps scaled dimensions before computing the recovered position, so shrinking a thin frame cannot create a height below 0.1%. If recovering a locked frame cannot satisfy both canvas fit and minimum dimensions, that action turns the lock off with a visible explanation; undo restores its prior state.

Canvas keyboard shortcuts are active only in DIY and only when focus belongs to the editor/canvas. Arrow keys move the selected unlocked layer 1 px, Shift+Arrow moves 10 px. Pending and confirmed coordinates share the same −100–200% schema clamp. Ctrl/Cmd+Z undoes; Ctrl/Cmd+Shift+Z or Ctrl/Cmd+Y redoes. Native chat inputs, textareas, number fields, selects and editable text keep their own keyboard behavior. Each key action and pointer gesture is one undo step. “收起面板” appears only during DIY and hides the property panel while keeping the draft, selection and pending preview; the persistent editing indicator’s “显示面板” restores it. Closing/canceling remains a separate action. For builtin background, the host contract is that “完整显示” uses the original image, while switching back to “铺满” restores scene animation; the property panel states this behavior.

Typography is `null` for native defaults, or `{family,fontSize,lineHeight,color,gradientStart,gradientEnd,gradientEnabled}`. Empty string / null means follow defaults. `fontSize` is pixels (10–48), `lineHeight` a multiplier (1–3); colors are hex CSS values. Editable width/height are 0.1–200%, blur is 0–40 px, particle count is 1–64, speed is a 0.05–8 multiplier. Real regions cannot hide, delete or rotate; removing a region override only restores its default geometry. The adapter is responsible for using CSS property setters and for restoring its previous styling when overrides disappear.

Brightness modes have independent projects. `refresh()` reloads the matching mode and cancels unsaved canvas edits when mode changes. The core also observes the root `class`, `data-theme`, `data-color-mode`, `data-mode` attributes. Hosts whose mode changes elsewhere must call `refresh()`. The adapter must not call core refresh from inside `apply`.

Palette property edits save immediately. In canvas DIY, edits are drafts until “保存并退出”; cancel/close/Escape restores the last successful saved project. New files first appear as a pending preview: property edits and drag handles work before confirm; cancel removes the preview while preserving the reusable library asset. Undo/redo track project and pending state. Reset preserves the asset library and a previous saved project recovery slot. A failed write leaves the last successful saved project intact and reports the error; the in-memory preview can still be exported.

IndexedDB `sunlit-tides-diy-v1` stores projects and assets; localStorage is not used. Project records are keyed `platform:mode`. Large imported images are stored once in the asset store; projects refer to asset ids. Builtin resources are stored/exported as builtin ids and `sourceRef`, without repeating bundled artwork. Share JSON contains both mode projects and all library assets. Region geometry lives under `layouts.codex` / `layouts.dsh`, so importing into another host does not apply the source host’s native layout.

“清理未使用素材” scans every platform/mode project and previous recovery slot in one read/write transaction. It also protects current draft, pending preview, staged imported modes, undo/redo history and asset-import reservations. Only assets with no references are deleted, with a count and freed-byte result. Clearing an editing session’s history (save/cancel/new session) makes abandoned preview assets eligible once no recovery slot references them. Active instances persist temporary `_session:*` reference records; each holds a Web Lock for its lifetime, so cleanup protects another window’s unsaved work and can prove that a closed/crashed window’s pin record is stale. Disposal removes its pin record and releases its lock. Where Web Locks are unavailable, cleanup preserves unconfirmed old session references and states that limitation instead of risking deletion.

Import validates schema/version, layer ids/kinds/numeric bounds, asset references, base64, MIME signatures, byte count, decoded dimensions and cumulative limits before one atomic assets/projects transaction. During canvas DIY, valid imported projects stay in the draft; cancel leaves both saved modes intact, while save commits both modes atomically. Their library assets remain reusable. Accepted imports are PNG/JPEG/WebP/GIF only. SVG files, URLs and executable content are rejected; builtin SVG stays a trusted adapter reference. Limits: 12 MiB per asset, 60 MiB library, 85 MiB JSON, 200 layers/assets, 16,384 px per edge and 64 million pixels. Failed imports cannot overwrite the previous project. `dispose()` removes global listeners and UI and restores adapter defaults; it never saves a canvas draft. Pending asynchronous load/decode results cannot reapply after disposal.

Run the isolated browser fixture with `node tests/diy-core.cjs` (Playwright and installed Edge, or `PLAYWRIGHT_EXECUTABLE_PATH`). `--serve` serves the fixture on a randomly assigned loopback port for interactive browser-tool acceptance. Evidence is written under `test-results/diy-core`.
